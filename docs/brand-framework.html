GSD Brand Framework

Single source of truth for color, type, components, and motion. Every new UI change reads from this file. Diverging from it requires deliberately updating this file — not adding a one-off to markup.

How to use this: when designing a new screen or modifying an existing one, find the relevant section here and use the documented class. If your need isn't covered, propose an addition to this file first, then implement.

Direction: lifestyle OS — soft, considered, calm-energetic. Pill-shaped controls, gentle shadows, warm neutrals, guava-700 as the single accent. Closer to Headspace/Strava than to Linear/Notion.

Identity

GSD is a personal lifestyle operating system. Single-tenant in practice, but designed like a polished consumer product. The aesthetic balances:

  • Calm — warm paper background, generous whitespace, no harsh contrast
  • Energetic — one decisive accent (guava-700), pill-shaped affordances, micro-interactions on tap
  • Considered — every chip and badge maps to a token; no one-off colors; consistent rhythm

The pill button (Variation B) anchors the whole direction. If you find yourself reaching for square corners and hairline borders, you're drifting into "productivity tool" — pull back.

Guava usage rules

  • 700 — primary CTA backgrounds, active tab indicator, accent dots
  • 800 — hover state for primary CTA backgrounds
  • 500 — focus borders, secondary accent (rarely)
  • 200/300 — destructive-button borders + hover
  • 50/100 — destructive-button surface, soft warning callouts

Motion

Four durations + one ease. Use the shortest duration that still reads as a transition (not a snap).

TokenValueUse for
--dur-fast120msHover/press state changes, color shifts
--dur180msDefault for property transitions
--dur-mid220msModal open, card expand
--dur-slow280msPage-level transitions
--easecubic-bezier(0.2,0.8,0.2,1)Everything (don't introduce new eases)
Active feedback: all .btn elements scale to 0.97 on :active. Don't add bounce or rotation — the scale-press is the canonical tactile feedback.

Iconography

Lucide-style outline icons. All inline SVGs must follow:

  • stroke-width: 1.8 (not 2, not 2.2 — 1.8 is canonical)
  • stroke-linecap: round, stroke-linejoin: round
  • fill: none, stroke: currentColor
  • Sizes: 14px (inline with text), 16px (inside .btn), 20px (toolbar), 24px (nav)

Common don'ts

Patterns that look right at a glance but drift the system. If you find yourself reaching for one of these, reach for the documented class instead.

Don't
Introduce a new button class for one screen.
.fancy-cta { ... }
Do
Use the documented role; add a modifier here if there's truly a new role.
<button class="btn btn--primary">
Don't
Inline font-size: 14px on a span.
<span style="font-size:14px;font-weight:600">
Do
Apply a role class on the closest container.
<span class="text-body">
Don't
Pick a new accent color (teal, purple, etc.) for "variety."
Do
Use guava-700 as the one accent. Earth chips carry semantic differentiation.
Don't
Use a different overlay backdrop tint per feature (slate, warm-brown, etc.).
Do
Use .overlay — one backdrop for every modal.
Don't
Add stroke-width 2 or 2.2 to icons.
Do
Always stroke-width: 1.8. Tightens the visual family.
Don't
Sharp corners on buttons or chips (border-radius: 4px).
Do
Pill for actions and chips. Sharp only for inputs and code blocks.
