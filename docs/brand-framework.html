GSD Brand Framework

Single source of truth for color, type, components, and motion. This file is the named version of what the app already looks like — not an aspirational redesign. Direction: Refined Brand (Variation A) — tightened proportions, consistent --r-md (4px) corners, flat surfaces, no decorative shadows.

How to use this: when designing a new screen or modifying an existing one, find the relevant section here and use the documented class. If your need isn't covered, propose an addition to this file first, then implement.

Color palette: --guava-700 is the single accent. Earth chips (sage/sky/clay/moss/slate/ochre/plum) carry semantic differentiation. No second accent color — if you reach for one, reach for guava with a different weight or one of the earth chips instead.

Identity

GSD is a personal lifestyle operating system. Single-tenant in practice, but designed like a polished consumer product. The aesthetic balances:

  • Calm — warm paper background, generous whitespace at the page level, no harsh contrast
  • Considered — every chip and badge maps to a token; no one-off colors; consistent rhythm
  • Compact — components are dense enough to fit real data on a 375px phone without scrolling for every detail. --r-md corners, 20px chip height, modest padding

If you find yourself reaching for fully-pill controls (r-pill) or soft shadows on buttons, you're drifting into "consumer wellness app" — pull back. The app reads as a tool that respects density, not a marketing page.

Motion

Use the shortest duration that still reads as a transition. Buttons + hovers = --dur-fast; cards + state = --dur; modals = --dur-mid. One ease for everything.

TokenValueUse for
--dur-fast120msHover/press state changes, color shifts on buttons
--dur180msDefault for property transitions
--dur-mid220msModal open, card expand
--dur-slow280msPage-level transitions
--easecubic-bezier(0.2,0.8,0.2,1)Everything (don't introduce new eases)
No press-scale on buttons. The app uses flat hover-color transitions only. Don't add transform: scale on :active — that's a lifestyle-app pattern that doesn't match the dense, utilitarian feel.

Hover + focus

Two canonical patterns — one for hover, one for focus. Both reuse a single token each so the convention is enforceable across the codebase.

Hover

TokenValueUse for
--row-hover-bg#fcfaf5Background fill on every hover state across the app

Faint warm white (between --bg and --surface). Reads as a gentle lift, not a darkening. Never use --surface-2 for hover — that's the beige seating-surface color, used as a resting background for things like sidebar/footer; on hover it competes with the page bg and reads heavy.

Two flavors

  • Plain bg-fill hover — buttons, dropdown items, sidebar nav, modal close, etc. Just :hover { background: var(--row-hover-bg); }.
  • Option 4 (left-accent + bg) — line-style rows on Home and elsewhere. 2px guava-700 border slides in from the left + warm bg + a 2px padding-left compensation so the content doesn't shift. Strongest "this is clickable" signal. Applied via .home-row.is-clickable, .home-event-row.is-editable, .home-note-card.
Don't add hover to elements that aren't actually clickable. Hover = click affordance. If an element has no click handler, it has no hover.

Focus

TokenValueUse for
--shadow-focus0 0 0 3px rgba(184,45,59,0.22)3px guava-700 ring on every focusable input + button

One ring, everywhere. Inputs change border-color to --guava-500 on focus + add the ring shadow. Buttons use :focus-visible with the same shadow (no outline). Don't introduce alternate focus styles.

Buttons

Single .btn base + role modifiers + size modifiers. r-md corners, no shadows, flat surfaces. Direction = Refined Brand (Variation A). Subsumes the legacy .btn-sm-accent / .btn-sm / .btn-add / .pill / .expand-action classes — those stay defined in app.css for un-swept call sites but new code uses .btn--*.

Overlays + modals

One overlay backdrop, one overlay-card. The existing .modal-overlay tint (rgba(20,30,80,0.45)) + 6px backdrop blur is canonical — don't pick a new tint per feature.

Iconography

Lucide-style outline icons. All inline SVGs must follow:

  • stroke-width: 1.8 (not 2, not 2.2 — 1.8 is canonical)
  • stroke-linecap: round, stroke-linejoin: round
  • fill: none, stroke: currentColor
  • Sizes: 14px (inline with text), 16px (inside .btn), 20px (toolbar), 24px (nav)

Common don'ts

Patterns that look right at a glance but drift the system. If you find yourself reaching for one of these, reach for the documented class instead.

Don't
Make buttons fully pill-shaped (border-radius: 999px) or add decorative shadows.
Do
Keep --r-md on buttons. Flat surfaces, no shadow on resting state.
Don't
Inline font-size: 14px; font-weight: 600 on a span.
<span style="font-size:14px;font-weight:600">
Do
Apply a role class on the closest container.
<span class="text-body">
Don't
Pick a new accent color (teal, purple, etc.) for "variety."
Do
Use guava-700 as the one accent. Earth chips carry semantic differentiation.
Don't
Use a different overlay backdrop tint per feature.
Do
Use .overlay — one backdrop for every modal (rgba(20,30,80,0.45)).
Don't
Add stroke-width 2 or 2.2 to icons.
Do
Always stroke-width: 1.8. Tightens the visual family.
Don't
Pill-shape chips (border-radius: 999px).
Do
Use --r-sm chips at 20px fixed height. Dense and consistent across the app.
