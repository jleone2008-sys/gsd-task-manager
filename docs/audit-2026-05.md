# GSD Tech-Debt Audit — May 2026 (Phase 2)

**Scope**: Investigate the two known UX regressions (Journal slowdown, beta cold-load legacy flash) plus broader tech debt across `src/*.js` and `beta/src/*.js`. Netlify functions deferred.

**Method**: Three parallel `Explore` passes (journal perf, beta load sequence, broad audit) + targeted reads to verify the most consequential claims before recommending fixes.

---

## Known issues — root causes confirmed

### A. Beta cold-load shows legacy view, then re-renders to new view

**Root cause**: `beta/app.html` script order interleaves beta core, legacy `src/*`, and beta home in that sequence:

```
beta/app.html:864  /beta/src/00-router.js           defer
              865  /beta/src/01-core.js             defer
              866  /beta/src/02-settings.js         defer
              867  /beta/src/03-journal.js          defer
              868  /src/02-tasks-sync.js            defer   ← legacy starts here
              ...
              878  /src/11-init.js                  defer   ← legacy /init/ fires
              879  /beta/src/05-brief.js            defer
              880  /beta/src/04-home.js             defer   ← beta home loads last
```

Because `defer` preserves document order, the legacy modules execute first and `src/11-init.js` (the legacy bootstrap) renders the prod task UI into `#taskContainer` *before* `beta/src/04-home.js` and `beta/src/01-core.js` get to call `renderHome()`. The user sees a single frame of legacy view, then a flash to the beta Home.

**Fix path**: Reorder script tags so beta modules load last, OR add an early "beta-active" gate that suppresses the legacy initial-render call until `renderHome()` is ready. The reorder is the cleaner single-file fix. (`src/11-init.js` is the legacy entry; gating it on a `window.__betaActive` flag declared by `beta/src/01-core.js` is a one-line change.)

**Severity**: Visible regression on every cold load. Quick win.

### B. Journal tab gets slower each day

Three reinforcing causes — all confirmed in code:

**B1. Full-DOM rerender of an unbounded timeline.**
`beta/src/03-journal.js:953-987`. `rerenderTimeline()` rebuilds the entire `#jTimeline` via `root.innerHTML = dates.map(renderDayCard).join('')` on every scroll-load. `loadOlderTimelineDays()` increments `journalState.timelineDays += 30` with no upper bound, so after several scrolls the rebuild operates on 200+ cards (each with photos, events, habit stats inline) on every subsequent rerender. The `IntersectionObserver` then re-attaches via `setupScrollObserver()` each pass — observer hygiene is OK (`obs.disconnect()` at line 1019), but the rebuild work dominates.

**Fix sketch**: Append-only incremental render. Instead of rewriting `innerHTML`, build the new card HTML in a fragment and `appendChild` it before the sentinel. The sentinel stays as the same DOM node, so the observer doesn't need to re-attach.

**B2. Global event listeners stay live on every tab.**
`beta/src/03-journal.js` has five top-level `document.addEventListener` blocks (lines 1434, 1639, 1667, 1682) attached at module load. They survive across tab switches and fire on every click/input/keydown anywhere in the app — each one runs `e.target.closest(...)` against multiple selectors before bailing. Not catastrophic on a fast laptop, but on mobile it shows.

**Fix sketch**: Either (a) early-out at the top of each handler when `activeTool !== 'journal'`, or (b) move the handlers into `renderJournal()` with an `_wired` flag matching the `_homeWired` pattern in `04-home.js:589`. Option (a) is one line per handler; option (b) is structurally cleaner.

**B3. In-memory state never evicts.**
`journalState.entries`, `journalState.calendarEvents`, `journalState.habitSummaries` are `Map`s that only grow. With 365+ days of journals, the `entries` map (which stores `photos[]` as data-URLs embedded in the row) can balloon into the hundreds of MB. The `rerenderTimeline()` then serializes those photos back into HTML each rebuild via `renderCardPhotos()`.

**Fix sketch**: For now, the cheapest mitigation is to fix B1 so the photos aren't re-serialized on every scroll. The deeper fix — move photos to Supabase Storage instead of data-URLs in the `photos[]` JSONB column — is a separate, larger phase. Document and defer.

## Broader audit — categorized

### HIGH

1. **Notes table loaded unbounded.**
   `src/06-notes.js:155, 162` — `db.from('notes').select('*').eq('user_id', ...)` with no `.limit()`. With 100+ notes per user this is fine; with 10k+ it isn't. Add `.limit(200)` + an infinite-scroll pattern when notes count crosses a threshold. Defer until count actually grows; flag for future.

2. **`habit_completions` loaded unbounded.**
   `src/03-habits-core.js:242-246` — same shape; no date filter, no limit. At 3 years × multiple habits/day this is a real row count. Add a "load last 6 months by default, lazy-load older on calendar drill-in" pattern.

3. **Note retry loops sequentially.**
   `src/02-tasks-sync.js:115-121` — `retrySyncAll()` runs `for (const n of notesArr) await saveNoteToDB(n);`. Only fires on retry after network failure, so the blast radius is small, but on a slow link this is O(n) sequential RTTs. Cheap win: `db.from('notes').upsert(notesArr.map(noteToRow))` in one call.

4. **`src/05-habits-editor.js` listener leaks.**
   30+ `document.addEventListener` calls registered at module load. Same pattern as journal — they survive across tabs. Same fix pattern: early-out when not on habits tab, or convert to a `wireOnce()` gated by `_wired`.

### MEDIUM

5. **`navigator.onLine` poll loop while offline.**
   `src/02-tasks-sync.js:44-46` — `setInterval(..., 30000)` only runs while the browser reports offline (cleared by the `'online'` event at line 41). Less bad than it first looks, but it shows a toast every 30s while offline — that's a UX nit. Toast once on offline, clear on online; no poll needed.

6. **Admin impersonate token persisted in `localStorage`.**
   `beta/src/01-core.js:793-805` — `gsd_admin_impersonate` key holds a Supabase session payload in localStorage (per the explore pass; verify in-place before changing). Tokens in localStorage survive browser-close and are reachable from any XSS. The right home is `sessionStorage` + a CSRF check on activation. Lower urgency in a private circle but worth documenting.

7. **Map-iteration lookups in habits.**
   `src/03-habits-core.js:106-108` — `for (const [sid, cid] of habitRowIdMap)` is O(n) per habit toggle. With a few dozen habits it's invisible; with hundreds it would show. Reverse-map (`clientId → serverId`) is a one-time fix.

### LOW

8. **Scattered magic numbers.**
   Debounce/timeout constants live inline across `04-home.js`, `03-journal.js`, `06-notes.js`, etc. (700, 300, 900, 5×60×1000…). A small `src/config.js` exporting named constants would make tuning safer, but the current values are sensible defaults; no behavior change needed today.

9. **Date helpers duplicated.**
   `jToday`/`jParseDate`/`jFormatDate` in `beta/src/03-journal.js` reinvent what `04-home.js` and several legacy files also implement. Worth consolidating into `lib/date-utils.js` once Phase 3 (beta→prod migration) lands and the file layout settles.

10. **Habit summary backfill is sequential.**
    `beta/src/03-journal.js:277-304` already batches the final upsert (`toWrite` array → one upsert call), so the loop body is local CPU work, not network. No fix needed.

## Inspected but not fixed (lower impact than initial agent claim)

- **Habits editor listeners** (`src/05-habits-editor.js:36, 405`): the two module-level `document.addEventListener` blocks gate on tightly-scoped selectors (`#habitFreqOptions .freq-btn`, etc.) and exit instantly on irrelevant clicks. Cost is one or two `closest()` calls per click on other tabs — not worth gating.
- **Polling loop while offline** (`src/02-tasks-sync.js:44-46`): the `setInterval` is *only* set inside the `'offline'` handler and cleared by the `'online'` event. Not a constant 30s wakeup. Lower impact than initially flagged.
